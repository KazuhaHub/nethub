# docs/ — NetHub documentation index

This is the index for NetHub's project documentation. It lists the documents
this directory holds or is planned to hold, with the status of each. Every
document here describes a design: no code exists yet.

| Document | Status | Purpose |
|---|---|---|
| [`DESIGN.md`](DESIGN.md) | **v0.3 draft (written in Chinese)** | The full architecture writeup: the decisions and the reasons behind them, the enroll/domain-claim flow, the `frps`/`frpc` SNI-passthrough tunnel design, the control plane as one Go binary with two runtime roles (`nethub web` and `nethub authz`) and its Postgres data model (see also the summary in `server/README.md`), console users and OIDC sign-in, the security design, the Weekend 0 to Weekend 7 plan, the roadmap, risks and disaster scenarios, the open questions (Q0–Q10), and the explicit v1 boundary (no config read, no firewall changes, no service restarts from the control plane). It describes a design only; no code exists. |

Derived from `DESIGN.md` §6, §9, §12 and §13, which remain the authority. |

## Contributing docs

If you want to help write any of the above, that's a welcome contribution —
see `CONTRIBUTING.md` at the repository root for how PRs, DCO sign-off, and
commit conventions work. Docs PRs follow the same process as code PRs.

A couple of standing rules that apply to every document in this directory,
not just the ones already listed:

- **No real deployment details.** No real hostnames, domains, IPs, ports, or
  credentials from anyone's actual deployment. Use `example.com`,
  `router.example.com` and `203.0.113.10` (an RFC 5737 documentation address)
  the way the rest of the project's public docs do.
- **Be honest about what's implemented.** Nothing is implemented yet: the
  repository holds documentation and the Weekend 0 kit only. v1's scope is
  intentionally narrow (remote Web UI access to OPNsense boxes behind
  CGNAT/dynamic IP, plus a multi-user console with OIDC sign-in; no config
  push, no fleet features). Config backup and delivery, bulk upgrades, and
  telemetry are roadmap items, not v1 features — and docs must describe the
  design as design ("is designed to", "will"), never as something that
  exists or works today.
