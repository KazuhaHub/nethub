- Mobile authenticated GUI passed; exact Alternate Hostnames required; rebinding and referrer checks remain enabled.

- NewUserConn contains the independently verified mobile IPv4 and matching registered identity. Denial blocks fresh mobile connections while an existing tab remains usable; heartbeats and registration stay online.

## Owner-confirmed decisions (2026-10-18)

- D5: retain 8443 for v1; neither measured mobile network triggered the port-sharing rule. Company/campus filtering remains unmeasured.
- D6: explicit 10-second application heartbeat and 30-second timeout; deny Login/NewProxy/Ping together on revocation. Retain the backend-outage availability cost and bound hook work internally. The backend hang trial confirms an availability risk: admin state can be stale and recovery can flap. Implementation must not claim an unconditional ten-second revocation bound under a hung hook.
- D7: implement NewUserConn source-IP gating after authenticated Open; use a 30-minute authorization window renewed by another explicit Open, without passive extension by arbitrary traffic. Existing connections may outlive this window. Shared CGNAT addresses do not identify a person; dual-stack behavior remains untested.
- D17: require manual exact Alternate Hostnames setup and explain it during enrollment; keep both security checks enabled and avoid writing unrelated system configuration.

## Experiment 6: final observations

Server-clock mode changes and frps log timestamps were used for disconnect timing.
Browser checks ran through the public relay with an authenticated Dashboard left open.
They used API fetches and failure events, rather than visual containers alone.

| Case | Observed behavior |
| --- | --- |
| Ping-only deny, at least 125 seconds | First server exit after 3.021 seconds; 25 exit events in the case log with repeated login/registration. API failures observed. Ping-only denial does not keep a device revoked. |
| Combined Ping/Login/NewProxy deny, at least 125 seconds | First exit after 4.012 seconds; no new proxy registration during denial. API unavailable; recovered after allow. |
| Three independent combined-denial trials | Exits after 2.136, 3.032, and 4.958 seconds. Recovery observed in about 2.96–3.08 seconds after allow. |
| Heartbeat disabled | No new Ping after changing interval to -1. Server heartbeat timeouts 30.008 and 30.009 seconds after registration; automatic reconnect could mask disruption between browser polls. Interval restored to 10 and strict config verification passed. |
| Backend process stopped for over 60 seconds | First exit after 2.016 seconds; API unavailable and login retries blocked. Recovery observed about 19.2 seconds after restarting the probe. |
| Backend Login/NewProxy/Ping HTTP 500 for over 60 seconds | First exit after 2.611 seconds; API unavailable and re-registration blocked. Recovery observed about 14.3 seconds after allow. |
| Backend Login/NewProxy/Ping hang 120 seconds | First server heartbeat-timeout log after 23.580 seconds; API failure sampled at 23.669 seconds. Admin status remained online through 118.7 seconds. It was offline at 124.4 seconds, usable at 135.4 seconds, offline/API failure again at 156.1 and 158.8 seconds, and usable again at 161.4 seconds. |

In the hang case, future requests switched to allow at 44.929 seconds; already
sleeping calls retained their 120-second delay. Repeated timeout logs do not mean
independent devices disconnected each time. A later allow write occurred near
156 seconds, and recovery was verified afterward. These are bounded observations;
continued stability beyond cleanup was not measured. Admin online status alone
cannot prove tunnel usability or completion of revocation during a blocked hook.

Backend outage is an availability dependency of Ping-based revocation. Timeout
and restoration behavior must be explicit in the design, and product hook work
must have bounded deadlines. Long-lived streams on a modified client that refuses
to close its session were not tested. Only the stock pinned client was used.

The repeat-and-timeout harness initially failed to match dotted TOML syntax;
that edit never changed the config. The corrected standalone timeout run passed.
A browser baseline attempt failed before injecting faults. Another process was
interrupted after a completed stopped-backend case; the independent restoration
timer restored original services. An initial hang assertion expected admin status
to become offline within 45 seconds; the contradictory state was preserved and
retested with longer observation. All failed/interrupted evidence remains private;
completed cases were combined explicitly rather than marking failed group files passed.
