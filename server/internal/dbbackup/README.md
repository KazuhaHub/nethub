# PostgreSQL archive groundwork

This internal package runs PostgreSQL 16 `pg_dump` as `nethub_backup`, using a private temporary passfile rather than a password argument. It publishes a custom-format archive only after the bounded producer exits successfully and the archive has been synced. A private atomic receipt records the hash, size, timestamps, role and tool version. An advisory lock excludes concurrent writers; incomplete outputs and temporary passfiles are removed.

Verification checks archive permissions, deployment binding, age and content hash. A recorded failed or overdue latest attempt is unhealthy even when an older successful archive remains available. State coherence checks prevent a receipt from another attempt, a mismatched archive date or an unsupported dump version from passing. The store's read-only backup preflight derives the fingerprint from the retained single-tenant database identity, independently of passwords or certificates. It refuses elevated roles, additional memberships, write privileges, executable security-definer functions and ambiguous tenant identity. The worker runs this preflight for each attempt.

Synthetic producer tests cover process failures, invalid headers, output limits, deadlines, contention, corruption and last-good preservation. The genuine PostgreSQL boundary suite separately restores an actual archive into an owned disposable database, compares forced-RLS device rows, removes backup `BYPASSRLS`, requires failure and restores the role before retrying. Raw archives contain sensitive data and must never be published as CI artifacts.

`VerifyWithBudget` provides a bounded full-file hash check for daily cycles and the deep doctor. `VerifyMetadata` deliberately checks only private receipt/file shape and freshness for routine worker health. Verification rechecks the recorded state before returning. Metadata health does not establish archive integrity, and hash verification does not establish successful recovery.

The daily worker is in [backupworker](../backupworker/README.md). Its CLI, retention and image/Compose integration passed the [scoped checkpoint](../../../deploy/validation-database-backups.md). The isolated database restore test does not establish the planned clean-host control-plane restore, retained-key recovery or enrolled-device reconnection. Those W7 requirements remain open.
